## Phase 1 — Import du référentiel RGAA (PR #2)

- **Version** : la racine du dépôt DINUM contient le **RGAA 4.1.2**, la version en vigueur. Le dossier `4.1/` n’est qu’une archive. Décision consignée dans l’ADR-0007 : copie octet pour octet, épinglée sur le commit `ca4019f`, avec un modèle typé dans `@rampe/core`.
- **Mise en œuvre** : par un sous-agent dans un worktree isolé. 12 tests verrouillent le référentiel :
  - 13 thématiques, 106 critères, 258 tests ;
  - numérotation contiguë ;
  - méthodologies en bijection avec les tests ;
  - tous les liens du glossaire résolvent.
- **Anomalies trouvées dans les données officielles** :
  - le critère 5.1 contient un lien relatif vers la spécification WHATWG, mort hors du site officiel ;
  - des objets `{}` vides dans `references` (12.11, 13.9, 13.11, 13.12) ;
  - 796 espaces insécables, à garder en tête pour toute comparaison de chaînes.
- **Relecture adversariale** : rien de bloquant, 5 points corrigés :
  - le script de synchro écrivait les versions en dur ;
  - il pouvait laisser un import à moitié écrit ;
  - deux tests étaient tautologiques ;
  - l’exception de lien n’était pas documentée ;
  - les liens internes au glossaire n’étaient pas testés.
- **Points écartés** : le gel profond des objets et les ligatures (YAGNI).
- **Leçon de workflow** : le relecteur choisi n’avait pas de shell et n’a pu faire qu’une lecture statique. Désormais, un relecteur doit pouvoir exécuter (règle ajoutée dans `workflow.md`).

## Phase 1 — Correspondance axe-core → RGAA (PR #3)

- **Découverte** : axe-core 4.14.0 porte des **étiquettes RGAA natives au niveau du test**, sur 67 règles sur 105. L’ADR-0008 s’appuie dessus au lieu du détour par WCAG prévu au départ.
- **Résultat** :
  - 67 règles rattachées directement au RGAA ;
  - 8 règles rattachées via WCAG, de façon indirecte. Pour le critère WCAG 4.1.2, ce rattachement est très imprécis : 17 critères RGAA à chaque fois ;
  - 30 règles hors RGAA. On y trouve des critères WCAG AAA ou 2.2 absents du RGAA 4.1.2, comme `target-size` (2.5.8).
- **Relecture adversariale**, avec un shell cette fois. Le relecteur a reclassé les 105 règles de façon indépendante et trouvé 0 écart. Deux défauts corrigés :
  - une étiquette RGAA inconnue (axe plus récent, par exemple) aurait été acceptée à l’exécution. Elle est désormais écartée et signalée dans `unknownRgaaTags` ;
  - le niveau `rgaa` aurait pu être lu comme « défaut certain », alors que 4 « bonnes pratiques » d’axe (`region`, `skip-link`…) y tombent. Elles sont désormais signalées par les drapeaux `bestPractice` et `experimental`. Le niveau qualifie la **précision du rattachement**, pas la certitude du défaut. C’est important pour l’ADR-0002.
- **Piège d’outillage** : le proxy rtk local réécrit `pnpm lint` en `eslint`. C’est documenté dans `CLAUDE.md`.

## Phase 1 — Synchro automatique du référentiel et Dependabot (PR #5)

- **ADR-0009.** Une PR ouverte par le `GITHUB_TOKEN` ne déclenche pas la CI. Le workflow relance donc lui-même `ci.yml` par `workflow_dispatch` sur sa branche, ce qui attache le check obligatoire. Le réglage « Actions peut créer des PR » a été activé sur le dépôt.
- **Deux écarts de l’implémenteur, validés** : il a fait mieux que la consigne.
  - Le jeton n’est jamais écrit dans `.git/config` : il passe par un en-tête éphémère et masqué (CICD-SEC-6).
  - Pas de `pnpm install` dans le job qui a les droits d’écriture (CICD-SEC-3).
- **Relecture adversariale** : rien de bloquant, trois défauts corrigés.
  - Un échec partiel (branche poussée, PR non créée) restait silencieux pour toujours. Le workflow est désormais idempotent et reprend là où il s’est arrêté.
  - Le test de comparaison laissait passer une comparaison par longueur. C’est prouvé puis corrigé par mutation.
  - **Un commit d’un fork pouvait passer pour un commit DINUM** : GitHub sert les commits des forks sous l’URL du dépôt parent. Le script exige désormais que le commit fasse partie de l’historique de `main` côté DINUM.
- **Ajouts** : délai de 7 jours avant toute montée Dependabot, cron décalé à 6 h 17 (les crons à l’heure pile sont les plus souvent retardés).
- **Risques acceptés, notés dans l’ADR** :
  - le téléchargement tourne avec des droits d’écriture, mais le contenu n’est jamais exécuté ;
  - GitHub désactive les crons après 60 jours sans activité.

## Phase 1 — Référentiel consultable sur le site (PR #9) : phase 1 terminée

- **ADR-0010.** Le texte officiel est affiché intact. Les 13 thématiques reçoivent une explication en langage simple, signée « Explication Rampe — non normative ». Chaque critère indique ce que l’audit automatique peut en détecter.
- **Rendu** : 124 pages statiques, sans aucun JavaScript côté client. Le HTML et le Markdown officiels sont assainis par liste blanche (OWASP *XSS Prevention Cheat Sheet*). Le relecteur a essayé une vingtaine de vecteurs XSS, tous neutralisés.
- **Accessibilité** : 0 violation axe sur les pages du référentiel, en thème clair et sombre.
- **Relecture adversariale, un point bloquant, et c’était le bon** : la page « ce que l’audit automatique détecte » **surestimait la couverture**. Des règles liées seulement via le critère WCAG 4.1.2 et des règles dépréciées par axe faisaient paraître « couverts » environ 12 critères sur 46. Corrigé :
  - les règles dépréciées sont exclues ;
  - les rattachements indirects sont présentés comme un « signal faible » ;
  - seul le rattachement direct compte.

  **Chiffre honnête : 33 critères sur 106 ont au moins une règle automatique directe.** Il confirme la position de l’ADR-0002 : l’audit humain est le cœur du produit.
- **Autres corrections** :
  - une numérotation officielle était altérée (méthodologie 10.14.2) ;
  - des liens `//hors-site` passaient l’assainissement ;
  - **7 formulations des explications** étaient inexactes. Par exemple, « pas de nouvelle fenêtre » laissait croire `target=_blank` interdit, alors que le RGAA n’interdit que l’ouverture sans action de l’utilisateur.
- **Reste à faire, hors périmètre** : la page roadmap du cockpit a une violation (cases à cocher sans étiquette). Elle sera corrigée dans une PR dédiée.

## Correctif — Cockpit sans case à cocher inaccessible (PR #10)

- La page roadmap du cockpit avait 23 cases à cocher sans étiquette (axe `label`, RGAA 11.1). Elles sont remplacées par un statut textuel « Fait » / « À faire ». axe ne relève plus aucune violation, en thème clair comme en sombre.
- **Relecture** : en contournant `render()` d’Astro, une future image dans `docs/` aurait été cassée sans aucun signal. On a ajouté un **garde-fou qui fait échouer le build**, et on l’a prouvé avec une doc sonde contenant une vraie image.

## Phase 2 — `rampe audit <url>` (PR #11)

- **ADR-0011** : Playwright + axe-core 4.14.0 dans un vrai Chromium, résultats rangés par critère RGAA, **aucun score**. Sorties : console en français, JSON versionné (`schemaVersion: 1`), et un code de sortie utilisable en CI.
- **Bac à sable conservé en CI** : Ubuntu 24.04 bloque les espaces de noms utilisateur dont Chromium a besoin. L’implémenteur a ajouté un profil AppArmor ciblé sur les binaires Playwright, comme le recommande la documentation Chromium, au lieu de recourir à `--no-sandbox`.
- **Relecture adversariale, un point bloquant** : une règle *bonne pratique* d’axe rattachée directement au RGAA (`region` → 9.2) sortait comme « non-conformité » et faisait échouer l’audit. C’était la seule raison de l’échec de service-public.fr. **Décision** : ces règles passent en « rattachement incertain, à confirmer par un humain » et ne font jamais échouer l’audit. Le tableau de l’ADR-0011 a été corrigé avant son merge.
- **Autres défauts réels corrigés** :
  - une page qui boucle à l’infini bloquait la CLI sans fin. Un délai global couvre désormais tout l’audit ;
  - une redirection en JavaScript faisait auditer une autre page. Désormais, une page finale hors http(s) est refusée, et un changement d’origine déclenche un avertissement ;
  - `bypassCSP` était inutile et désactivait une protection de la page. Il est retiré ;
  - les identifiants présents dans l’URL sont masqués dans toutes les sorties ;
  - les caractères de contrôle sont retirés de la sortie console.
- **Chiffre de référence, désormais unique** pour le site et la CLI (`isDirectCheck` dans `@rampe/core`) : **27 critères sur 106 ont une vérification automatique directe ; 79 n’en ont aucune.** Chaque rapport rappelle que les 106 demandent une vérification humaine.

## Leçons d’orchestration

- **Ne jamais enchaîner un nettoyage après un merge avec `;`.** Un merge refusé a quand même supprimé un worktree. Aucune perte, puisque tout était poussé, mais on n’utilise plus que `&&`.
- **Toujours suivre le run CI du commit de tête**, pas le dernier run listé. Un run plus ancien m’a fait croire à tort que la CI était verte, puis qu’elle était rouge.
