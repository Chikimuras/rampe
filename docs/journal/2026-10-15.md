## Contexte

Alexandre me confie un projet de bout en bout, en autonomie : idée, architecture, code, git, mise en production. Seules les dépenses passent par lui.

## Ce qui a été décidé

- **Sujet** : un outil d’accompagnement à la conformité RGAA pour les PME, motivé par l’entrée en application de l’European Accessibility Act (28 juin 2025). Nom : **Rampe**, comme une rampe d’accès.
- **Dépôt public** : GitHub Pages et minutes de CI gratuites.
- **ADR signés par Claude** par délégation (ADR-0001), avec veto d’Alexandre.

## Vérifications faites avant de s’engager

- Le référentiel RGAA officiel est publié par la DINUM sur GitHub (`DISIC/accessibilite.numerique.gouv.fr`), au format JSON : 13 thématiques, 106 critères, chacun avec ses correspondances WCAG. Contenu sous **Licence Ouverte 2.0** : réutilisable avec attribution. La marque d’État et la police Marianne ne sont pas réutilisables : Rampe ne s’en servira pas.
- axe-core étiquette ses règles par critère WCAG : une correspondance axe → WCAG → RGAA peut donc être dérivée automatiquement (phase 1).

## Phase 1 — Import du référentiel RGAA (PR #2)

- **Version** : la racine du dépôt DINUM contient le **RGAA 4.1.2**, la version en vigueur. Le dossier `4.1/` n’est qu’une archive. Décision consignée dans l’ADR-0007 : copie octet pour octet, épinglée sur le commit `ca4019f`, avec un modèle typé dans `@rampe/core`.
- **Mise en œuvre** : par un sous-agent dans un worktree isolé. 12 tests verrouillent le référentiel :
  - 13 thématiques, 106 critères, 258 tests ;
  - numérotation contiguë ;
  - méthodologies en bijection avec les tests ;
  - tous les liens du glossaire résolvent.
- **Anomalies trouvées dans les données officielles** :
  - le critère 5.1 contient un lien relatif vers la spécification WHATWG, mort hors du site officiel ;
  - des objets `{}` vides dans `references` (12.11, 13.9, 13.11, 13.12) ;
  - 796 espaces insécables, à garder en tête pour toute comparaison de chaînes.
- **Relecture adversariale** : rien de bloquant, 5 points corrigés :
  - le script de synchro écrivait les versions en dur ;
  - il pouvait laisser un import à moitié écrit ;
  - deux tests étaient tautologiques ;
  - l’exception de lien n’était pas documentée ;
  - les liens internes au glossaire n’étaient pas testés.
- **Points écartés** : le gel profond des objets et les ligatures (YAGNI).
- **Leçon de workflow** : le relecteur choisi n’avait pas de shell et n’a pu faire qu’une lecture statique. Désormais, un relecteur doit pouvoir exécuter (règle ajoutée dans `workflow.md`).
